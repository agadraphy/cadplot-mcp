# ADR-0007: Deterministic release-bound CycloneDX SBOM

**Status:** Accepted
**Date:** 2026-08-09
**Deciders:** CadPlot maintainers

## Context

CadPlot already audits the exact locked Python production set, .NET projects, vulnerabilities, and
declared Python licenses. A company security review also needs a standard machine-readable software
bill of materials that is bound to the exact release without exposing workstation paths, Autodesk
SDK binaries, company plot assets, or unsupported live-AutoCAD claims.

## Decision

Generate a deterministic CycloneDX 1.7 JSON SBOM from a passing dependency-audit report. The SBOM
contains the CadPlot application, locked Python runtime dependencies, and SHA-256-bound release
artifacts. It binds the exact Git commit, package version, `uv.lock`, and exported requirements.
Autodesk assemblies, company assets, test-only dependencies, workstation paths, and secrets are
excluded. The composition is explicitly `incomplete` because platform and licensed host components
are not redistributed. A strict offline validator rejects altered identities, hashes, dependency
graphs, evidence-boundary flags, duplicate components, and machine-local paths.

## Options Considered

### CycloneDX 1.7 JSON generated by the project

| Dimension | Assessment |
|---|---|
| Complexity | Medium |
| Portability | High |
| Offline verification | High |
| Path/data minimization | High |

**Pros:** Current standard, deterministic output, no new runtime dependency, exact release binding.
**Cons:** The project must maintain its strict profile validator and follow future schema revisions.

### SPDX

| Dimension | Assessment |
|---|---|
| Complexity | Medium |
| Portability | High |
| Existing project fit | Medium |

**Pros:** Mature standard and broad compliance tooling.
**Cons:** Adds a second vocabulary while current evidence maps directly to the CycloneDX component
and dependency model.

### Generator-only third-party CLI

| Dimension | Assessment |
|---|---|
| Complexity | Low initially |
| Reproducibility | Medium |
| Offline verification | Low to medium |

**Pros:** Less local code.
**Cons:** Adds a release-time dependency and does not by itself enforce CadPlot's path-redaction and
live-evidence boundaries.

## Consequences

- Demo and release kits can carry a standard, independently hash-checked component inventory.
- Identical audited inputs and artifacts produce identical component content and serial identity.
- Authenticode remains a separate external gate because it requires an organization-owned signing
  certificate and policy; an SBOM does not claim that binaries are signed.
- Future CycloneDX revisions require an explicit ADR/profile update instead of silently changing
  release evidence.

## Action Items

1. [x] Include and verify `cadplot-mcp.cdx.json` in demo and release kits.
2. [x] Add tamper tests for component hashes and evidence-boundary properties.
3. [x] Document optional validation with independent CycloneDX tooling.
